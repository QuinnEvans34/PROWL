# Documentation map

The repository contains two generations of documentation. Use this page to avoid treating completed
course-project plans or superseded proposal drafts as current instructions.

## Active capstone documentation

Start with [`capstone/README.md`](capstone/README.md). It defines the source-of-truth hierarchy,
current planning status, and the implementation-document sequence for PROWL.

## Completed five-week project documentation

The root-level technical documents in this directory—such as `architecture.md`, `training.md`,
`data-pipeline.md`, `implementation-plan.md`, and `schedule.md`—describe the completed five-week
PanTS project. They are valuable technical evidence and may be adapted, but they do not override the
approved capstone proposal or appendix.

The files under [`assignments/`](assignments/) and the repository's `deliverables/week2` through
`deliverables/week5` directories are historical course deliverables.

## Research and decision history

- [`experiments.md`](experiments.md) is the immutable experiment history. Do not rewrite old results.
- [`capstone-planning.md`](capstone-planning.md) is a valuable investigation log that includes
  superseded ideas and dead ends. It is evidence, not the active plan.
- [`SUBMISSION-READINESS.md`](SUBMISSION-READINESS.md) records important metric and external-evaluation
  compatibility findings. Its unresolved items are tracked as risks and requirements in the active
  capstone documents.
- [`ui-refactor-plan.md`](ui-refactor-plan.md) is a detailed UI design record. The active UI plan will
  identify which portions remain in scope for the approved capstone.

## Proposal-development artifacts

The repository currently preserves every proposal and appendix version, their source documents, and
the scripts used to generate later drafts. They will not be deleted or overwritten. A proposed
non-destructive reorganization is documented in
[`capstone/REPO-CLEANUP-PLAN.md`](capstone/REPO-CLEANUP-PLAN.md).
